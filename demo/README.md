# Synthetic local demo

All 240 school identities, their attributes and the five batches of hiring counts are generated by `data.ts`. Province and city names are geographical labels; demo school pins are city representative points, not actual campuses. No student, member, credential or production hiring record was copied.

Use Node.js **24.x**, then install the three lockfiles from the repository root:

```sh
npm ci
npm ci --prefix platform/api
npm ci --prefix admin-app
npm run demo
```

The launcher starts the public frontend on `http://127.0.0.1:8112`, the administrator frontend on `http://127.0.0.1:4174`, and the in-memory API on `http://127.0.0.1:8788`. All three bind only to the local loopback interface. `Ctrl+C` stops all three.

| Interface | Public demo identity | Public demo password |
| --- | --- | --- |
| Member | `13800138000` | `GridAtlasDemo123!` |
| Administrator | `demo-admin` | `GridAtlasDemo123!` |

These identifiers are intentionally public fixtures. They do not grant access to a deployed service. Session and encryption keys are generated at each startup. All edits and accounts reset when the demo exits. The launcher rejects `NODE_ENV=production`.

The demo exercises map previews, authenticated school rankings, Top 200 paging, per-grid and per-batch totals, and the distinction between schools located in a province and schools recruited into a province. Original protected documents, live eligibility determinations, real college entrance scores and production persistence are not included.

```sh
npm run test:demo
```

This command uses the real API and its authentication flow with an in-memory store. It checks the two ranking directions, five-batch reconciliation and member/admin separation without reading any private file or database.

To choose a different local API port, set `GRID_ATLAS_DEMO_API_PORT=8789` when starting the launcher. Frontend ports remain fixed; the launcher exits if a required port is occupied.
